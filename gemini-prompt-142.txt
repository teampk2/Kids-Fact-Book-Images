## SVG Recolor → Batch Preset Renderer – Fix “All SVG Collages (ZIP)” Export

### Current Problem

In the **SVG Recolor → Batch Preset Renderer** section, after processing the images, the **Collage Preview & Exports** section provides an option called:

**“All SVG Collages (ZIP)”**

However, when this option is exported, the ZIP contains **PNG files instead of SVG files**.

This is incorrect and must be fixed.

### Required Implementation

The **“All SVG Collages (ZIP)”** export option must generate and download **only SVG collage files**.

When the user selects:

**Collage Preview & Exports → All SVG Collages (ZIP)**

the workflow must be:

**SVG Processing → Generate SVG Collages → Package SVG files → ZIP download**

### Strict File-Type Requirement

* Export **SVG files only**.
* Every file inside the ZIP must have the `.svg` extension.
* Do **not** convert the collages to PNG.
* Do **not** render the SVG to a raster image before exporting.
* Preserve the SVG structure, vectors, paths, shapes, text, and transparency.
* The exported files must remain editable/scalable vector SVG files.

### ZIP Validation

Before creating the ZIP:

* Verify every generated collage is valid SVG content.
* Verify every filename ends with `.svg`.
* Ensure no `.png`, `.jpg`, `.jpeg`, `.webp`, or other raster files are included.
* Ensure the ZIP contains only the requested SVG collage files.

### Important

Do not change the behavior of other export options unless required.

Specifically, fix only:

**“All SVG Collages (ZIP)” → SVG Collages ZIP**

so that it no longer uses the PNG export/rendering pipeline.

### Expected Result

When the user clicks **“All SVG Collages (ZIP)”**, the downloaded ZIP should contain:

```text
collage-01.svg
collage-02.svg
collage-03.svg
...
```

and **never**:

```text
collage-01.png
collage-02.png
...
```

The exported collages must remain **true, high-quality SVG vector files** from generation through ZIP packaging and download.
