## SVG Recolor → Batch Preset Renderer – Fix “All SVG Collages (ZIP)” Export Logic

### Current Problem

In the **SVG Recolor → Batch Preset Renderer**, when the user clicks **“Generate All Preset Variations”**, all variations are processed successfully and the download options appear.

However, in the **Collage Preview & Exports** section, the **“All SVG Collages (ZIP)”** option is incorrectly connected to the PNG collage export logic.

As shown in the attached screenshot:

* **All SVG Collages (ZIP)** is displayed as an SVG export option.
* But clicking it results in **PNG Collages being downloaded**.
* The downloaded ZIP contains PNG files instead of the original SVG collage files.

This is a **file-type/export pipeline bug** and must be fixed at the source.

---

# Required Logic Fix

The export functions for **SVG Collages** and **PNG Collages** must be completely separated.

### SVG Export

When the user clicks:

**Collage Preview & Exports → All SVG Collages (ZIP)**

the application must execute **only the SVG collage export function**.

The workflow must be:

```text
Generate All Preset Variations
        ↓
Generate SVG Collages
        ↓
Collect SVG Collage Files
        ↓
Validate SVG File Type
        ↓
Create ZIP
        ↓
Download SVG Collages ZIP
```

The SVG export function must **never call or reference the PNG collage generator/exporter**.

---

# Strict SVG Requirement

The **“All SVG Collages (ZIP)”** button must contain **only genuine SVG collage files**.

Every file inside the downloaded ZIP must:

* Have the `.svg` extension.
* Contain valid SVG/XML content.
* Remain a vector SVG.
* Preserve SVG paths, shapes, text, and other vector elements.
* Preserve transparency where applicable.
* Not be rasterized into PNG.
* Not be converted to JPG, JPEG, WebP, or another image format.

### Example Correct ZIP

```text
All-SVG-Collages.zip
├── collage-01.svg
├── collage-02.svg
├── collage-03.svg
├── collage-04.svg
└── ...
```

### Incorrect Result — Must Never Happen

```text
All-SVG-Collages.zip
├── collage-01.png
├── collage-02.png
├── collage-03.png
└── ...
```

---

# Keep PNG Export Completely Separate

The existing:

**“All PNG Collages (ZIP)”**

button should continue to export PNG collages.

Therefore, the two buttons must have completely independent handlers:

```text
All SVG Collages (ZIP)
        ↓
SVG collage collection
        ↓
SVG ZIP generator


All PNG Collages (ZIP)
        ↓
PNG collage collection
        ↓
PNG ZIP generator
```

Do not share an export function that can accidentally substitute PNG files for SVG files.

---

# Important Code-Level Validation

Before adding any file to the **All SVG Collages ZIP**, validate the file.

For every file:

```text
if file.type === "image/svg+xml"
AND filename.endsWith(".svg")
AND content is valid SVG
    → add to SVG ZIP
else
    → reject the file and report the error
```

The SVG ZIP generator must **never accept PNG files**.

Likewise, the PNG ZIP generator should only accept PNG files.

---

# Prevent Filename/Extension Mismatch

Do not simply rename a PNG file from:

```text
collage-01.png
```

to:

```text
collage-01.svg
```

That is **not** a valid SVG export.

The application must use the **actual SVG collage source/content** when creating the SVG ZIP.

---

# Verify the Correct Data Source

After **Generate All Preset Variations**, maintain separate collections such as:

```text
svgCollages[]
pngCollages[]
```

The buttons must use the correct collection:

```text
All SVG Collages (ZIP)
        → svgCollages[]

All PNG Collages (ZIP)
        → pngCollages[]
```

Do not allow the SVG button to reference the PNG collection.

---

# UI Requirements

Keep the existing two options clearly separated:

### Download All Collages

**All SVG Collages (ZIP)**
→ Downloads **only SVG collage files**

**All PNG Collages (ZIP)**
→ Downloads **only PNG collage files**

The button labels must accurately represent the actual downloaded file type.

---

# Final Validation Before Download

When **All SVG Collages (ZIP)** is clicked, run these checks:

* ✅ Every selected file is an actual SVG.
* ✅ Every filename ends in `.svg`.
* ✅ SVG content is valid.
* ✅ No PNG files are included.
* ✅ No raster conversion occurs.
* ✅ ZIP contains only SVG collages.
* ✅ ZIP filename clearly identifies it as SVG.
* ✅ Downloaded files open correctly as SVG files.

If an SVG collage cannot be generated, **do not silently substitute a PNG**. Show a clear error identifying which SVG collage failed.

---

## Expected Final Behavior

After clicking:

**Generate All Preset Variations → All SVG Collages (ZIP)**

the application must download a ZIP containing **only the original/generated SVG collage files**.

The **All PNG Collages (ZIP)** option must remain completely independent and must continue downloading PNG collages.

### Critical Requirement

**Never allow the “All SVG Collages (ZIP)” button to fall back to, call, reference, or substitute the PNG collage export pipeline.** The file type must be enforced from generation through ZIP packaging and final download so this problem cannot occur again.
