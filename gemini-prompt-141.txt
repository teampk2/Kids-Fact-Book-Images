## KDP PDF Publisher – Automatic Safe-Margin and Page-Border Correction

### Problem to Fix

In the **KDP PDF Publisher** section, the PDF generated from the user's **Full Book Manuscript** can contain a page border/frame that extends too close to, or beyond, the **KDP safe margin** when the PDF is uploaded to KDP.

The attached screenshot shows the type of page-frame layout that needs to be corrected.

The PDF Publisher must automatically calculate and adjust the **page border/frame, Fact Box dimensions, and internal text-safe area** according to the selected KDP book size so that **no important element crosses the KDP safe area**.

---

# Required Implementation

After the PDF is generated from the **Full Book Manuscript**, the **KDP PDF Publisher** must perform an automatic safe-margin calculation before producing the final upload-ready PDF.

### 1. Detect the Selected Book Size

The logic must dynamically use the actual selected:

* Trim width
* Trim height
* Page orientation
* Bleed setting
* Interior type, where applicable

Do **not** use one fixed margin calculation for every book size.

The safe-area calculation must be performed independently for **each supported KDP trim size**.

---

# 2. Automatically Calculate the Safe Area

Create a dedicated safe-area calculation system:

```text
Page Size
   ↓
Trim Area
   ↓
Bleed Area (if applicable)
   ↓
KDP Safe Margin
   ↓
Safe Content Area
   ↓
Frame / Fact Box / Text Layout
```

All important content must remain inside the calculated safe content area.

### Important

The system must account for:

* Page border/frame
* Fact Boxes
* Text
* Headings
* Icons
* Images
* Page numbers
* Decorative elements
* Any other non-bleed content

Nothing that must remain inside the safe area should cross the calculated boundary.

---

# 3. Automatically Reduce the Page Border/Frame

If the existing page border/frame is too close to the trim edge:

* Automatically reduce its width/height.
* Move it inward as necessary.
* Maintain equal spacing from the relevant page edges.
* Preserve the original frame design.
* Do not distort the frame.
* Do not allow the frame to extend outside the calculated safe area.

The frame should be **scaled inward proportionally**, rather than simply being clipped.

---

# 4. Dynamically Adjust Fact Box Dimensions

Because reducing the page frame may reduce the available content area, the Fact Box layout must also be recalculated.

When necessary:

* Reduce Fact Box width slightly.
* Reduce Fact Box height slightly.
* Recalculate internal padding.
* Recalculate text width.
* Recalculate available text height.
* Reflow text naturally.
* Maintain consistent spacing between Fact Boxes.

### Important

Do not simply crop the Fact Boxes.

The entire Fact Box must remain inside the safe area.

---

# 5. Protect the Text Safe Margin

The internal text must also have sufficient clearance from the Fact Box edges.

When the Fact Box is resized:

```text
Fact Box outer boundary
        ↓
Internal padding
        ↓
Text safe area
        ↓
Text
```

The text must never touch or cross:

* Fact Box borders
* Page frame
* Trim boundary
* KDP unsafe region

If the available text width becomes smaller, the text should **reflow naturally** rather than overflow.

---

# 6. Preserve Existing Design

The correction should be as minimally invasive as possible.

Preserve:

* Existing Fact Box colors
* Typography
* Font sizes where possible
* Font weights
* Text colors
* Icons
* Border styles
* Page composition
* Overall visual design
* Existing spacing hierarchy

Only make the necessary geometric adjustments required to bring the content safely inside the KDP margins.

---

# 7. Use a Safety Buffer

Do not position the frame or content exactly on the calculated safe-margin boundary.

Create a small additional internal safety buffer so that minor rendering differences do not cause the content to cross the KDP safe area.

Conceptually:

```text
Trim Edge
│
│   KDP Safety Margin
│   │
│   │   Additional Safety Buffer
│   │   │
│   │   │  PAGE FRAME
│   │   │  ┌───────────────────────┐
│   │   │  │                       │
│   │   │  │      SAFE CONTENT     │
│   │   │  │        AREA           │
│   │   │  │                       │
│   │   │  └───────────────────────┘
│   │   │
```

The exact buffer should be calculated according to the selected trim size and KDP requirements rather than hard-coded as one universal value.

---

# 8. Automatic Preflight Validation

Before the final PDF is exported, run an automatic validation for **every page**.

Check:

### Page Frame

* Is the frame inside the safe area?
* Does any part of the frame cross the safe boundary?

### Fact Boxes

* Are all Fact Boxes inside the safe area?
* Does any Fact Box cross the safe boundary?

### Text

* Does any text extend outside its Fact Box?
* Does any text cross the page safe margin?
* Is any text clipped?

### Other Elements

* Are icons, images, headings, and page numbers safely positioned?

---

# 9. Automatic Correction Loop

If any element fails validation, automatically recalculate the layout.

For example:

```text
Generate PDF
      ↓
Calculate KDP Safe Area
      ↓
Check Frame
      ↓
Check Fact Boxes
      ↓
Check Text
      ↓
Check Images / Icons
      ↓
Any element outside safe area?
      ↓
   YES ──────────────┐
      ↓              │
Adjust dimensions    │
      ↓              │
Reflow content       │
      ↓              │
Validate again ──────┘
      ↓
   PASS
      ↓
Export Final KDP PDF
```

Do not export the final PDF until the validation passes.

---

# 10. Support All Book Sizes

Do **not** hard-code the current screenshot's dimensions.

The implementation must calculate the correct frame and content geometry for **every supported KDP trim size** selected by the user.

For each size:

```text
selected trim size
        +
bleed configuration
        +
KDP safe-margin rules
        ↓
calculate usable content area
        ↓
calculate frame dimensions
        ↓
calculate Fact Box dimensions
        ↓
calculate text-safe area
```

This must happen automatically.

---

# 11. Important: Do Not Solve This by Simply Shrinking Everything

The goal is **not** to blindly scale the entire page down.

Instead, intelligently calculate:

* Frame inset
* Content width
* Content height
* Fact Box dimensions
* Internal padding
* Text area
* Vertical spacing

The final design should remain visually balanced while safely fitting inside the KDP requirements.

---

## Expected Result

When a user generates a PDF in **Full Book Manuscript** and sends it to **KDP PDF Publisher**, the system should automatically produce a KDP-safe version.

The final PDF must ensure:

**Page frame → inside safe area**
**Fact Boxes → inside safe area**
**Text → inside Fact Box and safe area**
**Images/icons → inside safe area unless intentionally designed to bleed**
**No clipping → No overflow → No unsafe positioning**

The system should **automatically calculate, resize, reposition, reflow, validate, and correct the layout for the selected KDP book size before exporting the final PDF**, so the uploaded KDP PDF does not produce the border/frame warning shown in the attached screenshot.
